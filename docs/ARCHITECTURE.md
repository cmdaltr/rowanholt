# Rivendell DFIR Suite - System Architecture

**The map.** [`src/web/frontend/public/architecture/rivendell-architecture.html`](../src/web/frontend/public/architecture/rivendell-architecture.html) draws the whole platform as a map of Middle-earth (page 1) and Elrond's directed graph, branching by evidence type and OS (page 2). The web app shows it under **About**, and `rivendell map` opens it (`rivendell map gandalf` and `rivendell map journey` open the other two). It's generated by `scripts/docs/architecture/build_map.py`: edit the text there and rebuild, not the HTML.

**More pictures, also under About.** `gandalf-acquisition.html` (built by `scripts/docs/architecture/build_gandalf_flow.py`) shows Gandalf's three collectors, the order of volatility and the archive's path to Elrond. `rivendell-journey.html` is the whole platform as an interactive 3D journey across Middle-earth: Gandalf walks a Gandalf archive from the Shire (live hosts) past seven lanterns (the order of volatility) to the Brandywine Bridge (hashed and sealed), Bree (web UI, API and Redis), Amon Sûl (verified and mounted), one of three roads into Rivendell (processing, by OS), over the High Pass to Lothlórien (analysis), the Beacons of Gondor (one per ATT&CK tactic), Fangorn (timeline) and the palantír of Orthanc (export), with the case store under Erebor, Aragorn and the Navigator at Minas Tirith, the worker and Volatility's forge in Moria, datasets in Mordor, the cloud at the Grey Havens and Eru above it all; eagles carry disk and memory images, snapshots and datasets. Vendor badges name the software at each place, with its logo where Simple Icons has one (`vendor/logos/`, CC0 SVG data; listed in the page's `LOGOS`). Toggle Ollama to see Eru fall back to fixed answers. Each step is written out on screen as it happens and stays until the flow is complete; steps that need a flag (`--Memory`, `--Analysis`/`--Keywords`/`--Yara`, `--Timeline`, `--Splunk`/`--Elastic`, Gandalf's encryption, Ollama for Eru) are marked optional, on the list and with dashed amber labels on the map. It is hand-written against a vendored Three.js r160 (`public/architecture/vendor/`, MIT), so it works offline.

## 1. Overview

The Rivendell DFIR (Digital Forensics and Incident Response) Acceleration Suite is a comprehensive platform for automating forensic analysis workflows. It consists of three main components:

- **Gandalf**: Evidence acquisition module
- **Elrond**: Forensic analysis and artifact processing engine
- **Eru**: The AI analyst, with fixed answers from the case files when no model is available
- **Pippin**: Threat intelligence indicators that cases are matched against
- **Mordor**: Security dataset exploration and threat simulation
- **Aragorn**: Administration (Andúril for Rivendell's containers, the test lab)
- **Web Interface**: Unified control panel for all operations, including the case browser where a team flags and confirms findings

### 5.2 JWT Token Structure

```

│                     JWT TOKEN ANATOMY                     │
└──────────────────────────────────────────────────────────┘

HEADER:
{
  "alg": "HS256",           // Algorithm: HMAC SHA-256
  "typ": "JWT"              // Type: JSON Web Token

  "sub": "user-uuid-here",  // Subject: User ID

HMACSHA256(
```

### 6.2 Tables in Postgres today

The diagram above is the original design. What Postgres holds now, created by the Alembic migrations in `src/web/backend/alembic/versions/` (users live in a file store, `auth/users.py`, not in Postgres):

| Table | Holds | Migration |
|---|---|---|
| `jobs` | Every job: case number, sources, destination, options, status, progress, log, result | `3e5a9c1b7d20` |
| `job_access` | Each job's owner and who it's shared with (server mode) | `b7e4c2d9a810` |
